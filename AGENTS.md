- Creator/affiliate payouts go through Stripe Connect (Accounts v2 recipient) via src/lib/connect.server.ts: seller share is transferred on escrow release (not transfer_data at checkout) so escrow/disputes keep working; never store bank account numbers.
- Product public URLs use immutable, unique database-generated title slugs; resolve to UUIDs before purchase, access and referral operations so shared links survive title edits and legacy UUID links remain compatible. Use product-links helpers for canonical sharing and sitemap paths.
- Creator entry sections are shared frontend components on browse; link signup intent through the auth mode query and preserve next destinations without changing checkout or onboarding requirements.
- The first-30-creator launch offer is awarded only by the database trigger on product publication, with one permanent non-recycled slot per seller; public reads expose only launch slots and existing public profile/product fields, never client writes.
- Public creator cards and reviews read the public_creator_profiles view; never grant anonymous SELECT on profiles, because the full table contains private account fields.
- Legal pages share launch and revision dates through a browser-safe legal-dates module so document updates never silently backdate the service or amended terms.
- Contractual dispute limits live in a browser-safe legal-dispute-policy module with rule tests; they document manual operator handling, not automated payment release.
- Private product columns are read only through authenticated owner-scoped server actions; public and member catalogue grants expose explicit safe columns.
- Stripe fulfillment verifies raw-body signatures and event mode, then matches stored checkout identity, currency and exact amount before atomically promoting a pending order.
- Guest checkout never returns login tokens or confirms email ownership; guests verify their mailbox through the normal emailed sign-in link.
- Download queries are scoped to the signed-in identity and require a fresh successful authorization check before initiating a save.
- Stripe clients always use the connector gateway with an explicit environment; never fall back to direct secret-key SDK access.
- Exchange transitions and all item ownership are validated by database triggers so API callers cannot self-approve or substitute someone else's files.
- Privileged scans validate seller-prefixed paths before storage access; Stripe return URLs use an exact application-origin allowlist.
- RLS administrator checks delegate to the caller-scoped security-definer has_role function; never read user_roles through an invoker function used by that table's policies, because it recurses.
- Listing edits reuse the sell form with an edit identifier; owner-scoped server actions allowlist editable fields, preserve slugs, retain existing uploads, and requeue changed content for moderation.
- Product price reductions are derived by database triggers from private interval history; shared price presentation uses safe summaries and discloses limited history instead of inventing pre-tracking prices.
